# Notion Publishing Structure

Create or reuse one parent page named `Duply - Tawan`. This workspace is a readable mirror for collaboration; GitHub remains the source of truth. Search the workspace and check the Sync Registry before creating a page.

## Page Tree

### 00 Start Here

Plain-language product summary, current phase, next milestone, source repository, source commit, last sync, and links to every page below.

### 01 Product And Plans

Product definition, principles, Standard/Pro/custom B2B boundaries, business demos, and Phase 1 acceptance.

### 02 Approved Decisions

Readable mirror of `docs/tawan/DECISIONS.md`, including decision date and source commit. Leave status or owner `Unspecified` when the canonical record does not provide them.

### 03 Customer Journeys

LINE service journey, Sales Journey, Order, payment review, fulfilment, completion, Customer Memory, consent, tiers, and correction/deletion actions.

### 04 Architecture And Data

Store isolation, system boundaries, core entities, state machines, business modules, and known private-repository dependencies.

### 05 Security, Privacy And Thai Law

Security controls, launch blockers, retention, marketing, export, and legal-review status. Clearly label legal research as research, not legal advice.

### 06 Implementation Roadmap

Milestones, exit criteria, dependencies, and blockers, with Standard Phase 1 separated from post-Phase-1 Pro work.

### 07 Task Board

Database views for Backlog, Current Milestone, Blocked, Review, and Done.

### 08 Review And Questions

Friend comments, owner answers, unresolved questions, and review outcomes.

### 99 Archive

Superseded drafts and closed planning material.

### Sync Registry

Maintain one database under the parent page with `Page Key`, Notion page ID/URL, Git source path, source commit, sync status, and last sync. Reuse these records on every refresh. Creating a replacement page requires explicit human approval and archives the previous registry record.

## Generated Page Header

Create two top-level sections on every generated page:

- `Generated Snapshot (managed)`: AI-owned mirror content that may be replaced during sync
- `Human Review (preserved)`: friend comments, owner answers, and human-authored decisions that sync must never replace

Add this callout at the top of the managed section. Use `ChatGPT` for the initial ChatGPT import requested by the product owner; later tools must identify themselves accurately.

> AI generated by `<tool/account>` from the canonical GitHub records. Source commit: `<full 40-character SHA on the default or permanent protected branch>`. Last synchronized: `<date/time Asia/Bangkok>`. GitHub is authoritative. Only this managed section may be replaced during refresh.

## Markdown Sources

Add a visible `Markdown Sources` subsection inside `Generated Snapshot (managed)` on every generated page. Regenerate it during every sync and link every canonical Markdown file used to produce that page with a full 40-character commit-pinned GitHub URL:

`https://github.com/duplyofficial-thay/duply-creator/blob/<commit>/<path>.md`

The hub page must always link:

- `CONTEXT.md`
- `docs/tawan/DECISIONS.md`
- `docs/tawan/PRODUCT_SPEC.md`
- `docs/tawan/ARCHITECTURE.md`
- `docs/tawan/DATA_MODEL.md`
- `docs/tawan/SECURITY.md`
- `docs/tawan/IMPLEMENTATION_PLAN.md`
- `.agents/skills/tawan-project-handoff/SKILL.md`
- `.agents/skills/tawan-project-handoff/references/HANDOFF.md`

Require the commit to be reachable from the canonical remote's default branch or another permanent protected ref. After saving Notion, re-read the managed section and verify every link in the intended friend/AI access context. For a private repository, both the friend and AI integration must have GitHub access. Mark the handoff blocked when recipient access cannot be verified. Do not substitute local filesystem paths because another account or machine cannot open them.

## Task Board Properties

- `Task`: title
- `Type`: Epic, Task, Bug, Research, Decision, or Review
- `Status`: Backlog, Ready, In Progress, Blocked, Review, or Done
- `Phase`: Discovery, Phase 1, Transition Gate, Phase 2, or Later
- `Plan`: Standard, Pro, Shared, or Custom B2B
- `Area`: Product, Platform, LINE, Data, Security, Dashboard, Analytics, Campaign, Legal, or Operations
- `Owner`: person
- `Reviewer`: person
- `Priority`: Critical, High, Medium, or Low
- `Source`: GitHub file or issue link
- `Source Commit`: commit SHA
- `Acceptance`: short verification condition
- `Blocked By`: relation or text
- `Last Synced`: date/time
- `Generated By`: ChatGPT, Claude, Human, or Mixed

Do not use the Notion task status alone to claim code is complete. A Done engineering task must link to a committed Git change and its verification evidence.

## Sync Rules

1. Publish only committed content identified by a full 40-character SHA that is reachable from the canonical remote's default branch or another permanent protected ref.
2. Refresh generated summaries from Git in one direction: GitHub to Notion.
3. Discover the parent and Sync Registry before creation; reuse stable page IDs.
4. Replace only `Generated Snapshot (managed)` and preserve every human section, comment, and block outside it.
5. Move approved human decisions back into `docs/tawan/DECISIONS.md`, commit and push them with authorization, then refresh Notion.
6. Leave unavailable metadata blank or mark it `Unspecified`; never infer it.
7. Never copy secrets, credentials, raw Customer messages, payment evidence, or production personal data into Notion.
8. Mark pages `Out of sync` when their source commit is not the current approved remote commit.
9. Put historical or superseded material in `99 Archive`, with a link to its replacement.
10. Keep full-SHA Markdown source links inside the managed section on every generated page, regenerate them during each sync, and verify recipient/integration access.
